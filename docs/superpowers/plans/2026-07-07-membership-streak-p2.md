# Membership Streak — Phase 2 Implementation Plan (milestone config + auto-grant, dark)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Spec §6 (docs/superpowers/specs/2026-07-07-membership-streak-design.md) carries the full design; this plan sequences the edits. P1 (counter) is committed as 8007adc4.
> Commits require owner authorization (repo hard rule 1) — P1's commit was authorized this session.

**Goal:** Streak rungs exist as admin-configurable `MilestoneReward` rows that AUTO-GRANT free entries into the Major Draw when the streak counter crosses them — shipped dark (rewards seeded `isActive: false`; activation is a P3-launch runbook step).

**Architecture:** Extend the existing milestone engine (never a parallel system): new `streak-months` metric + `autoGrant` flag; auto-redeem reuses the proven atomic claim block; grants route through `DrawGrantService` with a first-class `streak` sourceKey threaded through every `entriesBySource` consumer. Generation-scoped re-earn via a `streakGeneration` stamp on issuances (unique index gains the dimension; the legacy index is dropped by the seed script).

## Global constraints
- Streak-granted entries are **excluded** from the `entries-gained` metric (no free-entry compounding — spec D6).
- Auto-grant must be crash-safe: issuance created `active` → auto-redeemed; an `active` issuance of an autoGrant reward found on a later sweep is self-healed (redeemed then, not lost).
- E11000 inside the rung loop = "already issued" → continue (never abort remaining rungs).
- No re-entrancy: the auto-grant's draw grant must NOT re-trigger `checkAndIssueMilestones`.
- `streak` (and the pre-existing missing `promo-link`) keys added to the **MajorDraw schema** — strict-mode drop footgun (MajorDraw.ts:241 comment).
- Norm lockstep in the same task: `MILESTONE_TYPES` enum + reward-shape additions in `src/lib/internal-norm/schemas/milestone-rewards.ts`, `npm run build:norm-manifest`, `docs/internal-norm/norm-context.md`; verify `norm:smoke` (needs dev server — run or flag).
- P2 stays dark: seed creates rewards `isActive:false`; markers (`status: "backfilled"`) inserted for pre-launch rungs BEFORE any activation.

## Tasks
1. **Models.** `MilestoneReward`: `MilestoneType` += `"streak-months"` (type + schema enum), new `autoGrant: boolean` (default false). `MilestoneIssuance`: enum += `"streak-months"`; status enum += `"backfilled"`; new `streakGeneration: number` (default 1); unique index becomes `{milestoneRewardId, userId, streakGeneration, achievementCycle}` (schema); legacy index `milestoneRewardId_1_userId_1_achievementCycle_1` dropped by the seed script (step 0).
2. **Evaluator.** `UserMilestoneMetrics` += `streakMonths`, `streakGeneration`; read from `user.subscription` (already selected). `entriesGained` subtracts the summed `entriesAmount` of the user's **redeemed `streak-months` issuances** (one indexed aggregate).
3. **Service.** Extract + export `resolveMetricValue(milestoneType, metrics)` (explicit `streak-months` branch — kills the loyalty-days fallthrough hazard) and `computeCycles(reward, metricValue)`. `checkAndIssueMilestones`: stamp `streakGeneration` (streak rewards use the user's generation; others stamp 1), include it in the dedupe query, wrap `create` in E11000 catch-continue, exclude `backfilled` from "existing" only for NON-streak logic (a backfilled row **blocks** re-issuance — that's its purpose), and after each streak-months issuance (or when finding an `active` one on an `autoGrant` reward) call the auto-redeem. `aggregatePerformanceByRewardIds` gains `backfilledCount` (excluded from `issuedCount`).
4. **Auto-redeem.** `RedemptionService.autoRedeemMilestoneIssuance(userId, issuanceId)` mirroring the atomic milestone-claim block (RedemptionService.ts:120-155): findOneAndUpdate active→redeemed, `$inc accumulatedEntries`, redemptionHistory row (`description: "Streak milestone — landed automatically"`), then `DrawGrantService.grantMonthlyCouponEntries(userId, amount, "streak", { skipMilestoneCheck: true })`.
5. **DrawGrantService.** Signature `grantMonthlyCouponEntries(userId, entries, sourceKey: "bonus-entry-promo" | "streak" = "bonus-entry-promo", opts?: { skipMilestoneCheck?: boolean })`; fresh-row `entriesBySource` gains `"bonus-entry-promo"|"streak"|"cancellation-upsell"` zeroed defaults; bucket write uses `sourceKey`.
6. **Draw plumbing.** MajorDraw TS interface + schema: add `"streak"` and the missing `"promo-link"` keys. `major-draw-queries.ts`: both per-user stat readers return a new `streakEntries` field; `oneTimeEntries` summation EXCLUDES `streak` (display fold-in happens in P3; streak is 0 until activation). `payment-processing.ts` `freshEntriesBySource`: add `"streak": 0`. `remove-draw-entries.ts` source unions + `unredeemMilestoneRedemption`: streak-months issuances reverse from the `streak` bucket (others stay `bonus-entry-promo`). `src/types/payment-ledger.ts` comment updated.
7. **Norm lockstep.** `MILESTONE_TYPES` += `"streak-months"`; reward schema += `autoGrant`; `MilestoneRewardWithPerformance` += `autoGrant` + `backfilledCount`; `npm run build:norm-manifest`; `docs/internal-norm/norm-context.md` note; `npm run norm:smoke` (or flag if server unavailable).
8. **Seed script** `scripts/seed-streak-milestone-rewards.ts` (`seed:streak-rewards[:dry]`): step 0 drop legacy issuance index (try/catch); create 6 rewards `isActive:false, autoGrant:true, neverExpires:true` — (2,+100) (4,+200) (6,+300) (8,+400) (10,+500) non-recurring + (12,+600) `isRecurring:true`, codes `STREAK-2R … STREAK-12R`; insert `backfilled` markers for every user rung `threshold <= streakMonths` (recurring: cycles ≤ floor(streak/12)), stamped with the user's generation; `--activate` flag flips `isActive:true` (P3 launch runbook only).
