# Promo — Architecture

## Promo types

| Model | What it represents |
|---|---|
| `Promo` | A promo offering (code, multiplier, bonus, etc.) |
| `PromoLink` | A trackable share link tied to a promo (UTM-style) |
| `ScheduledPromo` | A promo bound to a date range (auto-activate / auto-expire) |
| `AlternatingPromoMultiplier` | A multiplier that alternates between values on a schedule |
| `PromoBannerText` | Text content for the site-wide banner |
| `PromoAnalyticsVisit` | Per-visit analytics row for promo pages |
| `BonusEntryPromo` | Bonus draw-entries promo |

## Landing hero countdown tier (drawn-tonight / drawn-tomorrow, 2026-06-24)

The landing hero swaps to dedicated "drawn tonight" / "drawn tomorrow" art keyed to the draw's **AEST calendar day**, distinct from the rolling-hours `mar-*` root hero. Two helpers in [`promo-hero-images.ts`](../../src/utils/promo/promo-hero-images.ts) compute urgency:

- [`getLandingHeroUrgencyFromDrawDay(draw, now)`](../../src/utils/promo/promo-hero-images.ts) — **calendar-day (AEST)** tier driving the landing hero. Returns `"drawn-tomorrow"` when today's AEST day is the day immediately before the draw's AEST day; `"drawn-tonight"` when today **is** the draw's AEST day and `now` is before the draw moment; otherwise `null`. Uses `drawDate` only (independent of the entry-freeze window), and never returns `final-hours` (landing art ships no such tier). DST-safe — it compares AEST midnight-of-day epochs via `formatInTimeZone` + `createAESTDateAsUTC`. Example: draw 27th 8:30pm AEST → all of the 26th = `drawn-tomorrow`; 27th 00:00–8:30pm = `drawn-tonight`; after the draw moment = `null`.
- [`getMajorDrawHeroUrgencyFromMajorDraw(draw)`](../../src/utils/promo/promo-hero-images.ts) — the existing **rolling-hours** tier (24h / 48h / 72h to `min(draw, freeze)`) that still drives the root `mar-*` hero via [`getPromoImagePaths`](../../src/utils/promo/promo-hero-images.ts). Unchanged.

Wiring: [`getLandingHeroImagePaths(slug, urgency)`](../../src/config/promo-landing-slugs.ts) is now actually called **with** the calendar-day urgency in [`PromoHero`](../../src/components/sections/promo/PromoHero.tsx) and [`ToolsetLandingPage`](../../src/app/promotions/_components/ToolsetLandingPage.tsx) (preload). Previously urgency was always `null` — the tiers were scaffolded but never connected.

## Landing hero image resolution (2026-05-12)

[`landing-image-resolver.ts`](../../src/utils/promo/landing-image-resolver.ts) builds URLs for promo-landing heroes under `public/images/background/promo/landing/{brand}/`. Filename grammar: `{brand}-{milTB|sidTB|kinTB}{-dark}?{-mobile}?{-drawn-tomorrow|-drawn-tonight}?.webp`. (No landing toolbox ships `-final-hours` art — a `final-hours` request collapses to base; see resolution order below.)

Drawn-tier stills ship **light-only** (4 brands {dewalt,makita,milwaukee,ryobi} × 3 toolboxes {milTB,kinTB,sidTB} × 2 states × 2 viewports = 48 webp), generated by [`scripts/convert-drawn-tonight-tomorrow-to-webp.ts`](../../scripts/convert-drawn-tonight-tomorrow-to-webp.ts) alongside the 2 `bg-*` stage backgrounds — dark mode falls back to light via step 2 below.

Not every variant ships, so the resolver consults a build-time manifest at [`src/generated/landingImageManifest.ts`](../../src/generated/landingImageManifest.ts) — emitted by [`scripts/build-landing-image-manifest.ts`](../../scripts/build-landing-image-manifest.ts) during `prebuild`/`predev` — to avoid 404s when one mode is missing and fall back to the opposite mode.

**2026-06-12 — winning A/B hero promoted to default.** The promo-hero A/B test concluded with **variation 2** winning, so its art replaced the per-brand defaults under `landing/{brand}/` and `landing/all-prizes/`. Variation 2 ships a single image per `{brand}-{toolbox}` viewport with **no separate dark art** — the copy populated the `-dark` / `-dark-mobile` filenames with the same image, so light and dark now render identically. The `landing/variation{1,2}-{desktop,mobile}/` source folders were then emptied (kept on disk via a `.gitkeep`) so they're ready to stage the next A/B hero test. This also added the previously-missing `{brand}-sidTB.webp` / `{brand}-sidTB-mobile.webp` light bases for all four brands, so light `sidTB` no longer falls back to the dark file. Regenerate the manifest (below) after any such asset swap.

Resolution order inside [`resolveLandingHeroImage`](../../src/utils/promo/landing-image-resolver.ts):

1. Build the requested URL. If it's in the manifest → return.
2. Build the opposite-mode URL (light↔dark). If it's in the manifest → return that.
3. **A requested urgency tier isn't in the manifest in either mode → drop the tier and resolve the base hero** (general rule, replaces the old kinTB-specific short-circuit). Because **no landing toolbox ships `-final-hours` art**, a `final-hours` request collapses to base for every toolbox; `-drawn-tomorrow` / `-drawn-tonight` resolve to the real shipped art.
4. Base hero not shipped in either mode → return the originally-requested URL so the 404 surfaces visibly.

`kinTB` now ships its own `-drawn-tomorrow` / `-drawn-tonight` countdown art like the other toolboxes (only `-final-hours` collapses to base). Evergreen (`all-prizes/`) uses the same path for both modes by design and ships **no countdown art** — [`resolveEvergreenHeroImage`](../../src/utils/promo/landing-image-resolver.ts) falls back to the base all-prizes collage when an urgency variant is absent from the manifest.

**Shared stage background.** [`LANDING_HERO_BACKGROUND`](../../src/utils/promo/landing-image-resolver.ts) (`{ desktop, mobile }` under `landing/background/bg-{desktop,mobile}.webp`) is the empty hero "stage" the brand heroes are composited onto — rendered in place of the gray skeleton while hero data loads so the load-in is seamless.

Regenerate the manifest after dropping in new assets:

```bash
npm run build:landing-manifest
```

Regression tests: `npm run test:landing-image-resolver` (kinTB drawn tiers resolve to real art; `final-hours` collapses to base) and `npm run test:landing-draw-day-urgency` (calendar-day AEST `getLandingHeroUrgencyFromDrawDay`).

## Landing hero video (2026-06-12)

[`landing-video-resolver.ts`](../../src/utils/promo/landing-video-resolver.ts) is the **video twin** of the image resolver: a prize slug maps to one hero clip per viewport under `public/videos/landing/{brand}/`, named exactly like its `.webp` hero — `{brand}-{milTB|sidTB|kinTB}{-mobile}.{webm,mp4}`. `getLandingHeroVideoPaths(slug, urgency=null)` returns `{ desktop, mobile }`, each carrying a `webm` + `mp4` URL, or **`null`** when `slugToBrandKey` is null (`cash-prize`, evergreen `all-prizes`) so the caller keeps the image hero.

On the `drawn-tomorrow` / `drawn-tonight` calendar-day tier it swaps to the animated badge clip `{brand}-{toolbox}{-mobile}-drawn-{state}.{webm,mp4}` (96 drawn clips, webm+mp4, generated by [`scripts/convert-drawn-tonight-tomorrow-videos.ts`](../../scripts/convert-drawn-tonight-tomorrow-videos.ts) via ffmpeg). `final-hours` / `null` keep the base hero clip.

Deliberately **simpler than the image resolver — no manifest, no build step, no light/dark fallback**:
- The A/B-won hero ships **one clip for both themes** (light === dark), so there's no opposite-mode swap to resolve.
- Every brand × toolbox combo has a clip on disk, so existence is deterministic from the slug — no manifest lookup needed.
- Per-browser codec selection is the browser's job via `<source>` order (WebM first, MP4 fallback); a missing/!-decodable WebM falls through to the MP4 automatically.

Assets: each `.mp4` (H.264, no audio, 5 s loop — desktop 2560×1044, mobile 1080×1164) has a VP9 `.webm` sibling (~50–65 % smaller) generated with `ffmpeg -c:v libvpx-vp9 -b:v 0 -crf 33 -an`. Re-run that per file when new clips are dropped in; the `videos-desktop/` / `videos-mobile/` staging folders (`.gitkeep`-kept) hold raw numbered drops before they're identified and renamed into the brand folders.

Consumed by [`PromoHero`](../../src/components/sections/promo/PromoHero.tsx) via [`LandingHeroVideo`](../../src/components/sections/promo/LandingHeroVideo.tsx) — see [docs/shared-ui/frontend.md](../shared-ui/frontend.md) for the poster / gating behaviour.
